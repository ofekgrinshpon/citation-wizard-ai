# Global Paper Coherence for Academic Writing Mode

## Goal
Make every new chapter explicitly aware of what previous chapters **claimed, defined, and cited** — not just their raw prose — and block contradictions / repetitions before the chapter is finalized.

## Current state (audit)
- `write_chapter` prompt already injects `previousChapters` (truncated 2,000 chars each), thesis line, line of argument, this chapter's role + counter-arguments, and sibling chapter titles.
- Intro / conclusion / abstract use `buildPaperLevelContext` with full chapter bodies.
- Critic pass exists per-chapter (`critic.ts` / `criticRevision.ts`) but does **not** see other chapters.
- No structured representation of prior claims, definitions, or cited sources.

## Proposed design — three additions, no schema migration

### 1. Paper Memory (structured ledger, regenerated incrementally)
A compact JSON object the wizard owns and ships with every `write_chapter` call:

```text
PaperMemory {
  thesis: string
  claims:        [{ chapter, claim, stance, citationKeys[] }]   // 1–3 per chapter
  definitions:   [{ term, gloss, chapter }]                      // locked terminology
  counterAddressed: [{ chapter, counter, resolution }]
  citedSources:  [{ key, shortForm, chapter, footnote }]         // for Rule 37.7 hint
  styleFingerprint: { avgSentenceLen, registerTag, hedgingLevel }
  openQuestions: [{ chapter, question }]                         // for later chapters to close
}
```

Generated by a small **`paperMemoryExtractor`** edge call right after each chapter finalizes — Gemini 2.5 Flash, JSON-mode, ~600 output tokens. Runs in `EdgeRuntime.waitUntil` so it never blocks the user. Cached on `academic_sessions.metadata.paper_memory` (jsonb already supported under `metadata`-like fields — store inside `chapters[i]`).

### 2. Pre-write priming
`write_chapter` prompt grows a new block (rendered only when memory is non-empty):

```text
=== זיכרון העבודה עד כה ===
תזה: ...
טענות שנטענו:
  פרק 1 — <claim> (תומך/מסתייג)
  פרק 2 — <claim> ...
מונחים נעולים (אל תגדיר מחדש):
  <term> = <gloss>
מקורות שכבר צוטטו (השתמש ב"שם" / "לעיל ה"ש X" אם רלוונטי):
  <shortForm> — ה"ש X בפרק Y
שאלות פתוחות שייתכן שהפרק הנוכחי סוגר:
  ...
```

Replaces today's prose-snippet dump for the body of prior chapters; the raw 2,000-char slices stay as a fallback for the **immediately preceding** chapter only (continuity of voice).

### 3. Coherence critic (extends existing critic pass)
After draft, before final, run a second critic prompt with:
- Current chapter draft
- Paper Memory
- Titles + 1-paragraph summary of each prior chapter

It returns JSON:
```text
{ contradictions: [...], repetitions: [...], terminologyDrift: [...], unresolvedCounters: [...] }
```

If any array is non-empty → trigger `criticRevision` with those findings as the revision brief. Single retry, then accept (same pattern as today's critic).

## Files to change

- `supabase/functions/legal-qa/paperMemory.ts` *(new)* — extractor + types + serializer.
- `supabase/functions/legal-qa/index.ts`
  - In `write_chapter` prompt builder: render Paper Memory block when present.
  - In `write_chapter` handler: after `criticRevision`, run new coherence critic; persist updated Paper Memory via `waitUntil`.
- `supabase/functions/legal-qa/critic.ts` — add `runCoherenceCritic(draft, paperMemory, chapterSummaries)`.
- `src/hooks/academic/useAcademicWizard.ts` (or equivalent) — read/write `paper_memory` on the session, pass it in the `write_chapter` body.
- Frontend: send `paperMemory` alongside `previousChapters`.

## Rollout
- Behind `PAPER_COHERENCE_ENABLED` env flag (default `true` after one shadow day).
- Shadow A/B: log `paper_memory` + coherence-critic findings into `qa_logs.metadata.coherence` even when flag is off, to size impact.
- Telemetry: count `contradictions_found`, `repetitions_found`, `revision_triggered`, p95 added latency. Target: +≤1.5s per chapter, ≥30% of multi-chapter papers trigger at least one revision.

## Out of scope
- Cross-paper memory (between separate papers).
- Re-writing already-finalized chapters when a later chapter contradicts them (we only adjust the *new* chapter).
- Embedding-based similarity for repetition detection — start with the LLM critic; add embeddings only if false-negatives are high.
