## Implemented boundaries
- All four existing hosts resolve typed responses through `citationPlanner.ts`; its pure `citationCompletion.ts` gate has no IO, telemetry, persistence, request IDs or billing ownership.
- Kind, request/canonical input binding, optional response raw echo, jurisdiction, supplied identity values, matching identity anchors and contradictory identifier anchors are checked before added fields are used.
- `identity.matched` is distinct from completeness. Additions require an allowed field, `grounded[field] === true`, exact provenance value, an existing matching donor URL, meaningful matching donor title and existing extraction basis. URL/source ID alone is insufficient. Discovery-only titles must relate to the identity, including the grounded title for identifier-led articles.
- Identity/record conflicts stop completion. Explicit non-identity field conflicts quarantine the implicated field; supplied values remain exact. Compatible expanded article bylines confirm but do not replace supplied abbreviations. Remaining missing fields and quarantined additions are warned explicitly.
- Unsupported/malformed/unavailable/unmatched typed responses are terminal preservation or supported partial rendering, never generic content. Matched-but-unrenderable case responses now warn rather than throw `EMPTY_RESPONSE`; transport/retry/refund ownership is unchanged.
- Safe case choices and deterministic local rendering now use aligned capabilities. Complete local cases/statutes/articles and terminal safety outcomes do not add requests. Specialized book formatting warnings are identical across hosts.
- Bibliography displays the specific completion warning even when missing-field markers are also present; stored warning aggregation was already present.

## Payload compatibility and limitations
- Inspected real `ForeignLookupResult` construction for case, article, statute, book and chapter before acceptance changes. No server file or wire envelope was changed; no deployment is required. Current case/article/book/chapter extraction results do not echo raw input, so binding uses the retained request and server-produced anchors; an optional echo is checked if present. Statute version 1 remains mandatory.
- Captured public article Search data is replayed through the production extractor. Case/statute/book/chapter test responses are generated by the real extractor over synthetic mocked Search evidence, not claimed live captures.
- Older payloads lacking the existing grounding/provenance/anchor evidence remain displayable as warned supplied-only results on normal and raw-bound recovery paths. Unbound historical recovery records retain their old bounded display-only compatibility branch; it is not evidence of newly verified identity and cannot dispatch requests. This residual legacy branch is not claimed to have strict C1 acceptance parity.
- The client checks the existing server extraction attestation; it does not reacquire source documents or independently prove each extracted value. Generic book/chapter extraction has limited publication fields; no invented editor/chapter metadata or new rule packs were introduced.
- Unknown spans and supplied provenance remain in the pasted evidence contract. Accepted additions and provenance are exposed as resolution metadata; hosts' existing storage/history schemas are unchanged.
